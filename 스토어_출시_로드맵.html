1부 · 정식 앱 기능 확장

PHASE 0

현황 진단과 기술 경로 결정

본격적으로 계정을 만들기 전에, 어떤 방식으로 앱을 패키징할지부터 정해야 이후 단계가 낭비 없이 진행됩니다.

0.1

현재 스택 확인

public/manifest.json, public/sw.js, public/offline.html이 이미 존재 — 즉 이미 설치 가능한 PWA입니다. 지도는 네이버 Maps Dynamic Map(NCP), 데이터는 Notion API를 Cloudflare Workers가 프록시하는 구조이며, 이미지용 R2 버킷(yukjindae-map-images)도 바인딩되어 있습니다.

0.2

패키징 방식 선택

옵션 A — TWA(Bubblewrap): Android만 노릴 때 가장 빠르지만 iOS엔 쓸 수 없음.

옵션 B — Capacitor(Ionic): 기존 vanilla JS 코드를 거의 그대로 WebView에 얹어 Android/iOS 동시 대응.

옵션 C — 전면 네이티브 재작성: 이 프로젝트 규모 대비 과함.

0.3

핵심 결정 확정

패키징은 Capacitor, 데이터베이스는 Cloudflare D1, 로그인은 구글·카카오·네이버 소셜 로그인 직접 구현, 관리자 권한은 운영진 / 슈퍼관리자 2단계로 확정하고 아래 단계를 진행합니다.

PHASE 1

데이터 기반 전환 (Notion → Cloudflare D1)

회원·제보 기능이 들어가면 Notion API의 초당 요청 제한과 트랜잭션 부재가 바로 병목이 됩니다. 이미 Workers·R2를 쓰고 있으니 네이티브로 붙는 D1이 가장 무리 없는 선택입니다.

1.1

D1 스키마 설계

places / festivals / courses / banners 등 기존 Notion 데이터베이스 구조를 관계형 테이블로 재설계합니다.

1.2

Notion → D1 이관 스크립트

Notion API로 기존 데이터를 모두 읽어 D1에 적재하는 1회성 ETL 스크립트를 작성합니다.

1.3

worker.js 프록시 로직 교체

Notion API 호출 부분을 D1 쿼리로 바꾸되, 프론트엔드가 받는 응답 포맷은 그대로 유지해 public/js 쪽 변경을 최소화합니다.

왜 Postgres가 아닌가

D1은 SQLite 기반이라 대량 동시 쓰기엔 약하지만, 이 앱처럼 읽기가 압도적으로 많고 쓰기는 제보 정도로 적은 구조엔 정확히 맞습니다. 나중에 정밀 반경 검색(PostGIS)이나 무거운 분석 쿼리가 필요해지면 Hyperdrive로 Neon/Supabase Postgres에 붙이면 되고, 지금 스키마 규모라면 그때 가서 이전해도 비용이 크지 않습니다.

PHASE 2

회원 인증 (구글·카카오·네이버 로그인)

호스티드 인증 서비스 대부분은 카카오·네이버를 지원하지 않아, 세 곳을 다 붙이려면 결국 직접 구현과 큰 차이가 없습니다. 셋 다 표준 OAuth2라 Workers의 fetch만으로 구현 가능합니다.

2.1

회원 스키마 설계

users(role: user / 운영진 / 슈퍼관리자), oauth_accounts(provider, provider_user_id), sessions 테이블을 설계합니다.

2.2

소셜 로그인 앱 등록

구글 클라우드 콘솔, 카카오 디벨로퍼스, 네이버 개발자센터에 각각 앱을 등록하고 리다이렉트 URI를 지정합니다.

2.3

OAuth2 콜백 핸들러 구현

구글은 OIDC라 id_token 검증으로 깔끔하게 처리되고, 카카오·네이버는 access_token을 받은 뒤 각자의 프로필 API(카카오 /v2/user/me, 네이버 /v1/nid/me)를 호출하는 방식으로 구현합니다.

2.4

세션 발급 & 검증

Workers는 stateless이므로 JWT 또는 D1 세션 테이블 + 쿠키 방식 중 하나를 선택해 구현합니다.

검수 리드타임

카카오·네이버는 이메일 등 확장 프로필 항목을 쓰려면 각 개발자센터에서 앱 심사를 거쳐야 합니다. 계정을 만들자마자 되는 게 아니므로 이 단계는 가장 먼저 신청해두세요.

PHASE 3

장소 제보 기능

로그인 기반이 있어야 의미가 있는 기능이라 Phase 2 이후에 진행합니다.

3.1

제보 테이블 설계

place_submissions(status: pending/approved/rejected, submitter_user_id) — 사진은 이미 바인딩된 R2 버킷(yukjindae-map-images)을 그대로 재사용합니다.

3.2

제보 폼 UI

로그인한 사용자만 접근 가능한 “장소 제보” 폼을 추가합니다.

PHASE 4

관리자 콘솔 (운영진 / 슈퍼관리자)

권한을 두 단계로 나누기로 했으니, 화면과 API 모두 역할별로 분리해서 설계합니다.

4.1

운영진 권한

제보 검토·승인·반려, 기존 장소 정보 수정 권한을 가집니다.

4.2

슈퍼관리자 권한

운영진 임명/해제, 장소 직접 등록·삭제, 전체 통계 열람 권한을 가집니다. 운영진 권한 위에 상위 권한만 추가되는 구조로 설계해 권한 체크 로직을 단순하게 유지합니다.

4.3

관리자 라우트 보호

역할 확인 미들웨어로 /admin 계열 라우트와 API를 감쌉니다.

PHASE 5

안전장치 & 개인정보 정비

회원가입과 제보 기능이 생기면서 늘어난 리스크를 여기서 한 번에 정리합니다.

5.1

어뷰징 방지

로그인·제보 엔드포인트에 rate limiting을 적용합니다.

5.2

개인정보처리방침 갱신

회원가입으로 새로 수집하는 항목(소셜 로그인 식별자, 이메일 등)을 반영해 방침을 갱신합니다.

5.3

회원 탈퇴 처리

정보통신망법에 따라 탈퇴 시 개인정보 파기 절차를 구현합니다.

2부 · 스토어 출시

PHASE 6

법률·행정 준비

스토어 심사보다 먼저, 그리고 별도로 진행해야 하는 항목들입니다.

6.1

사업자등록 필요 여부

앱이 무료이고 광고·결제가 없다면 사업자등록은 필수가 아닙니다. 인앱결제나 광고 수익화를 계획한다면 사업자등록과 이후 세무 신고가 필요합니다. 구글·애플 개발자 계정 자체는 개인 명의(Individual)로도 개설 가능하며, 조직 계정으로 하려면 사업자등록증과 D-U-N-S 번호가 필요합니다.

6.2

위치기반서비스사업 신고

지도 위에 장소를 표시·검색하는 기능은 위치정보법상 “위치기반서비스”에 해당할 가능성이 높습니다. 방송통신위원회(실무 접수는 한국인터넷진흥원 KISA)에 위치기반서비스사업 신고가 필요합니다. 신고 자체는 무료지만 처리 기간이 있으므로 스토어 제출 훨씬 전에 미리 진행하세요.

놓치기 쉬움

단순 지도 표시를 넘어 “내 주변” 같은 실시간 GPS 개인 위치 수집 기능을 넣는다면 개인위치정보 처리에 대한 추가 의무(손해배상 책임보험 가입 등)가 발생할 수 있습니다. 기능을 확정하기 전에 KISA에 사전 문의로 해당 여부를 확인하는 것을 권장합니다.

6.3

저작권·콘텐츠 점검

네이버 지도 API 약관상 상업적 배포 시 사용량 구간별 과금이 적용되고, 지도 내 네이버 로고·저작권 표기를 임의로 제거할 수 없습니다. 스토어 등록 전에 네이버클라우드플랫폼 콘솔에서 배포될 앱의 패키지명(Android)/Bundle ID(iOS)와 서비스 URL을 추가 등록해야 지도가 정상 동작합니다.

프로젝트 루트의 지역별 자료(서울_서울근교_BEST.pdf, 전라도.pdf, 충청도.pdf 등)에 포함된 사진·글이 육진대 구성원이 직접 촬영·작성한 것인지, 다른 블로그나 SNS에서 가져온 이미지가 섞여 있지는 않은지 다시 확인하세요. 스토어 등록은 노출도가 크게 늘어나는 시점이므로 출처가 불분명한 이미지는 교체하거나 사전에 사용 허락을 받아두는 것이 안전합니다.

확인 권장

앱 이름 “육진대”의 상표 충돌 여부를 특허청 키프리스(KIPRIS)에서 미리 검색해보세요. 서비스가 커질 경우를 대비해 상표 출원도 선택지로 고려할 만합니다.

PHASE 7

개발자 계정 & API 준비

계정 승인에는 며칠씩 걸릴 수 있으므로 기술 작업과 병행해서 최대한 먼저 신청하세요. 소셜 로그인용 개발자 콘솔 등록은 Phase 2에서 이미 진행합니다.

7.1

Google Play Console 개발자 등록

$25, 1회 결제로 평생 유효합니다. 결제 정보와 신원 확인이 필요하며 승인까지 며칠 소요될 수 있습니다.

7.2

Apple Developer Program 등록

$99/년, 매년 갱신이 필요합니다. 개인(Individual) 명의로 충분하며 신원 확인에 1~2일 소요될 수 있습니다.

7.3

네이버클라우드플랫폼 콘솔 갱신

기존 웹 도메인 외에 앱에서 사용할 패키지명/Bundle ID와 배포 URL을 추가 등록해야 지도 API 키가 정상 동작합니다.

7.4

커스텀 도메인 소유권 확인

TWA 방식을 병행한다면 Digital Asset Links(assetlinks.json)를 실제 소유한 도메인에 호스팅해 소유권을 검증해야 합니다. 현재 Cloudflare Workers 배포 도메인이 개인 소유 커스텀 도메인인지 확인하세요.

PHASE 8

앱 패키징 (기술 작업)

Capacitor 기준으로 진행한다고 가정한 작업 목록입니다.

8.1

Capacitor 프로젝트 초기화

기존 public/ 정적 자산을 그대로 번들링하거나, 라이브 URL을 원격 콘텐츠로 로드하는 방식(server.url 설정) 중 선택합니다.

8.2

아이콘 & 스플래시 스크린

기존 icon-192/512, maskable 아이콘을 iOS의 여러 해상도, Android adaptive icon 규격에 맞게 재출력합니다.

8.3

네이티브 권한 설정

위치 권한을 쓴다면 iOS Info.plist에 NSLocationWhenInUseUsageDescription 문구가 필수이며, Android는 AndroidManifest.xml에 권한을 선언해야 합니다.

8.4

“앱다움” 보강

네이티브 공유 시트, 즐겨찾기 로컬 저장, 푸시 알림 중 최소 1~2개를 추가해 단순 웹뷰 이상의 기능을 갖추는 것이 좋습니다.

애플 리젝 위험

App Review Guideline 4.2(Minimum Functionality)는 웹사이트를 그대로 감싼 앱을 명시적으로 반려 대상에 포함합니다. 이미 있는 오프라인 캐싱(sw.js)에 더해, 네이티브다운 기능을 최소 한두 개 얹어야 첫 심사 통과 가능성이 높아집니다.

8.5

실기기 테스트

Android 실기기·에뮬레이터와 iOS 실기기(시뮬레이터는 위치·카메라 등 일부 기능이 제한됨) 양쪽에서 지도 로딩, 오프라인 모드, 소셜 로그인, 제보 플로우, 딥링크를 확인합니다.

제출 & 심사
