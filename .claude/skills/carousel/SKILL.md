# 육진대 인스타 캐러셀 만들기

디자인 시스템은 `instagram-carousel/carousel.css`, 형식·함정은
`instagram-carousel/README.md`, 시작점은 `instagram-carousel/template.html`.
**셋을 먼저 읽고** 그 형식을 따른다. 여기엔 작업 순서만 적는다.

## 1. 소재부터 확인한다

- **사진을 받았으면** 전부 훑어보고(Read 로 실제로 본다) 표지에 깔 12장,
  본문에 크게 쓸 대표컷 3~5장을 고른다. 흔들렸거나 얼굴이 크게 박힌 사진은 뺀다.
- **앱 기능이면** 코드에서 실제 동작을 먼저 확인한다(`public/js/*.js`).
  화면에 없는 기능을 슬라이드에 쓰지 않는다.
- 무엇을 알리는 게시물인지 한 문장으로 정리한 뒤 슬라이드를 나눈다.
  표지 → 뭐예요? → 본문 3~5장 → 꼭 확인해주세요 → 댓글 CTA, 9장 안쪽.

## 2. 숫자는 확인된 것만

앱 숫자(장소·축제·코스·수유실)는 README 의 curl 로 그날 값을 받아 쓴다.
행사 숫자(참가 인원 등)는 운영진이 준 값만 쓴다. 모르면 그 슬라이드를 뺀다.
추정하거나 지난 캐러셀 숫자를 재사용하지 않는다.

## 3. 슬라이드를 짠다

```bash
cd instagram-carousel
cp template.html slides-<주제>.html
```

`carousel.css` 의 컴포넌트만 조합한다 — 새 색·새 폰트 크기를 만들지 않는다.
소재별로 쓸 컴포넌트는 README 의 카탈로그 표에 있다.

앱 화면이 필요하면:

```bash
node tools/serve.mjs &
BASE=http://localhost:8799 GEO=<lat,lng> node tools/shoot.mjs '[...]'
```

`GEO` 는 장소가 몰린 곳으로(기본 `37.5340,126.9860`). 사용자가 보낸 실기기
스크린샷은 내 위치가 실제 위치라 **그대로 쓰지 않고** 같은 화면을 다시 찍는다.

## 4. 렌더하고 이름을 붙인다

```bash
node tools/render.mjs slides-<주제>.html out-<주제>
cd out-<주제> && i=1; for f in t*.png; do mv "$f" "$(printf '%02d' $i)-slide.png"; i=$((i+1)); done
```

## 5. 움직임이 필요하면 녹화한다

정지 화면으로 전달이 안 되는 기능만. `tools/slide/course-video.html` 을 본떠
페이지를 만들고 `node tools/record.mjs <url> out/NN-slide.mp4 9`.
mp4(업로드용)와 gif(미리보기용)가 같이 나온다.

## 6. 눈으로 확인한다

렌더한 PNG 를 **직접 열어 본다.** 자주 나는 사고:

- 말풍선 줄바꿈이 깨져 한 글자만 다음 줄로 넘어간다 → 문구를 줄이거나 `<br>` 고정
- 말풍선이 중요한 정보를 가린다 → 위치 클래스(`--tl/--br/--foot`)를 바꾼다
- 캡처에 팝업(설치 유도·튜토리얼)이 찍혔다 → `shoot.mjs` 로 다시 찍는다
- 사진이 인물 중심인데 4:5로 잘려 얼굴이 반만 남는다 → `object-position` 조정

## 7. 넘긴다

- `out-<주제>/01~NN-slide.png` (+ 영상 슬라이드 `mp4`/`gif`)
- 업로드 순서
- 캡션 전문 (`caption.md` 형식: 해시태그 → 오픈 → 페인포인트 → 핵심 → 참고 → 댓글 CTA)
- 미리보기 아티팩트 링크 — 영상 슬라이드는 **GIF 로** 넣는다(data: mp4 는 재생이 막힌다)
